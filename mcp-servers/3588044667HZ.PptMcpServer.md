# PptMcpServer — PowerPoint MCP 服务器（VSTO 插件）

一个 PowerPoint VSTO 插件。插件随 PowerPoint 启动时自动在 `127.0.0.1:5100` 运行本地 HTTP 服务器，
通过 MCP（Model Context Protocol）的 Streamable HTTP 传输暴露 53 个操作 PowerPoint 的工具。
AI 客户端（如 Claude Desktop）可以直接连接，实时操控当前打开的演示文稿，
所有修改立即在 PowerPoint 界面中可见。

## 环境要求

- Windows + PowerPoint 2013 及以上（推荐 2016 / 2019 / Microsoft 365）
- Visual Studio 2019 或 2022（安装 **Office/SharePoint 开发** 工作负载，含 VSTO 工具与 Office PIA）
- .NET Framework 4.8 开发者包（VS 自带）
- Claude Desktop（或其他 MCP 客户端）

## 构建与运行

1. 用 Visual Studio 打开 `PptMcpServer.sln`（NuGet 包会自动还原）。
2. 选择 **Debug | Any CPU**，按 **F5**。Visual Studio 会启动 PowerPoint 并自动加载插件，
   插件启动后 Kestrel 监听 `http://127.0.0.1:5100/mcp`。
3. 命令行构建（已在本仓库 `tools\nuget.exe` 验证通过）：
   ```
   tools\nuget.exe restore PptMcpServer.sln
   "D:\VisualStudioCommunity\MSBuild\Current\Bin\MSBuild.exe" PptMcpServer.sln /p:Configuration=Debug
   ```
   说明：packages.config 项目需要先用 nuget.exe 还原包（msbuild 的 `/t:Restore` 对
   packages.config 无效）；VSTO 的 `Microsoft.VisualStudio.Tools.Office.targets`
   会按已安装 VS 的版本自动探测（`$(MSBuildExtensionsPath32)\Microsoft\VisualStudio\v18.0\OfficeTools`），
   无需额外传参。

> 注意：本机需先安装过 VSTO 运行时（VS 安装 Office/SharePoint 工作负载时自动安装）。
> 若构建报清单签名错误（MSB3325），在项目属性 → 签名 页重新生成测试证书即可
> （仓库已附带 `PptMcpServer_TemporaryKey.pfx`，空密码）。

## 配置（可选）

插件目录下会自动生成 `mcp.config.json`：

```json
{
  "Host": "127.0.0.1",
  "Port": 5100,
  "LogDirectory": null
}
```

- `Host`：出于安全考虑**只能**是 `127.0.0.1`（代码强制收敛为回环地址，禁止远程连接）。
- `Port`：1-65535，修改后需重启 PowerPoint 生效。
- `LogDirectory`：日志目录，默认 `%APPDATA%\PptMcpServer\Logs`。

## 在 Claude Desktop 中配置

1. 启动 PowerPoint，确认插件已加载（PPT 启动时插件自动运行；查看日志
   `%APPDATA%\PptMcpServer\Logs\pptmcp.log` 确认 "HTTP 服务已启动"）。
2. 编辑 Claude Desktop 配置文件（Windows 路径）：
   ```
   %APPDATA%\Claude\claude_desktop_config.json
   ```
   添加：
   ```json
   {
     "mcpServers": {
       "ppt": {
         "type": "http",
         "url": "http://127.0.0.1:5100/mcp"
       }
     }
   }
   ```
3. 重启 Claude Desktop，在工具列表中即可看到 `ppt` 服务器的 12 个工具。

## 手动测试

```bash
# 健康检查
curl http://127.0.0.1:5100/health

# 握手
curl -X POST http://127.0.0.1:5100/mcp -H "Content-Type: application/json" -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'

# 列出工具
curl -X POST http://127.0.0.1:5100/mcp -H "Content-Type: application/json" -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'

# 调用工具：添加一张空白幻灯片
curl -X POST http://127.0.0.1:5100/mcp -H "Content-Type: application/json" -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add_slide","arguments":{"layout":"blank"}}}'
```

也可用官方 [MCP Inspector](https://github.com/modelcontextprotocol/inspector) 连接
`http://127.0.0.1:5100/mcp` 调试。

## 架构与线程模型（必读）

```
Kestrel 线程池线程                    PowerPoint 主 UI 线程（STA）
┌──────────────────────┐   Send()   ┌─────────────────────────────┐
│ McpHttpMiddleware    │ ─────────► │ ThisAddIn_Startup 安装的     │
│  → McpProtocolProcessor           │ WindowsFormsSynchronization │
│  → Tool → PowerPointService       │ Context（隐藏控件锚点）      │
│       │ _marshaller.Invoke(...)   │  → PowerPoint COM 调用       │
└──────────────────────┘            └─────────────────────────────┘
```

- PowerPoint 的对象模型必须在**主 UI 线程**调用，否则会抛 COM 错误
  （RPC_E_WRONG_THREAD）。
- VSTO 环境下 `SynchronizationContext.Current` 默认为 `null`，插件启动时
  （`PowerPointThreadMarshaller.Install`，此时代码正运行在主线程）安装一个
  `WindowsFormsSynchronizationContext` 并创建隐藏控件锚点 —— PowerPoint 自己的
  消息泵会处理投递给该控件的消息，从而把 Kestrel 线程池线程的回调"搬"回主线程。
- `PowerPointThreadMarshaller.Invoke<T>` 用 `Send` 同步封送（请求/响应语义）；
  若调用方已在主线程则直接执行，避免死锁。异常通过 `ExceptionDispatchInfo`
  原样重抛（保留 COMException 等原始类型与堆栈）。
- 已运行中的请求会阻塞 Kestrel 线程池线程直到 PowerPoint 主线程处理完；
  若 PowerPoint 正被全屏放映（`run_slideshow`）阻塞，工具调用会等待放映结束。

## 版本说明：为什么用 ASP.NET Core 2.2 而不是 6.0

VSTO 插件必须运行在 .NET Framework 4.8 进程中（POWERPNT.EXE 是原生进程，无法承载
.NET Core/.NET 5+ 运行时），而 **ASP.NET Core 6.0 的程序集依赖 .NET 6 运行时，
在 .NET Framework 进程中加载会直接抛 FileLoadException**。ASP.NET Core 官方
支持 .NET Framework 的最后一个版本是 2.2（Kestrel 可在 net48 上运行），
因此本项目使用 ASP.NET Core 2.2 + Kestrel 自托管，行为与 6.0 一致。

## 保存文件注意事项（必读）

插件会对演示文稿进行实时修改，请务必注意以下保存事项：

- **构建/测试前先保存**：本项目的构建测试（F5 调试、`msbuild`、自动化测试）会启动/重启
  PowerPoint 进程，**所有未保存的演示文稿可能丢失**。运行前请先保存并关闭正在编辑的文档。
- **只操作"当前激活"的演示文稿**：所有工具作用于 PowerPoint 中**当前处于激活状态**的
  演示文稿（`ActivePresentation`）。同时打开多个文档时，请确认目标文档是激活的那个
  （工具返回的 `full_name` 可用来核对）。
- **修改立即生效且不可撤销**：`delete_slide`、`update_shape`、`add_animation`、
  `set_slide_background` 等工具对文档的修改**立即写入内存中的文档**，无法通过本服务器撤销。
  重要操作前请先手动保存（Ctrl+S）或备份原文件。
- **保存请通过 PowerPoint 完成**：插件不提供保存工具，保存（Ctrl+S）与另存由 PowerPoint
  界面操作；`export_to_pdf` 只导出 PDF，不会保存当前演示文稿。
- **更新/重装插件后需重启 PowerPoint**：替换插件文件或重新安装（双击 `.vsto`）后，
  正在运行的 PowerPoint 不会加载新版本，请保存文档后重启 PowerPoint。
- **不要在有未保存文档时强制结束 PowerPoint 进程**：更新测试、端口调试等场景若需
  结束 `POWERPNT.EXE`，请先保存所有文档，否则未保存的修改会全部丢失。

## 常见问题

- **端口被占用**：修改 `mcp.config.json` 的 `port` 并重启 PowerPoint；
  日志中会出现监听失败记录。
- **"当前没有打开的演示文稿"**：先在 PowerPoint 中新建/打开一个演示文稿再调用工具。
- **图表添加失败**：PowerPoint 图表依赖 Excel 组件（ChartData 工作簿），
  请确认机器已安装 Excel 或 Office 完整版（精简版可能缺少）。
- **防火墙弹窗**：仅监听 127.0.0.1 回环地址，通常不会触发防火墙。
- **AI 连不上**：确认 PowerPoint 已启动且插件加载成功（看日志），
  用上方 curl 健康检查排查。
- **证书/信任提示**：重新生成测试证书（项目属性 → 签名 → 创建测试证书），
  并勾选"信任对 Visual Studio 生成的 Office 解决方案的访问"。

## 安全

- 服务器只监听 `127.0.0.1`，不接受任何远程连接（代码强制）。
- 请求体限制 1MB；参数经过 JSON Schema 声明 + 运行时强校验。
- 所有操作仅作用于当前已打开的演示文稿，不会读取演示文稿以外的文件
  （`add_image`/`apply_design`/`export_to_pdf` 仅使用客户端明确给出的路径）。
