## 它能做什么

给定原始资料、项目需求、演讲场景或参考风格后，自动完成：

1. 理解任务、观众与演示目标；
2. 清理、筛选和重组原始材料；
3. 选择最合适的叙事结构；
4. 自动确定合理的页数和章节比例；
5. 为每页规划核心观点、内容、证据与页面角色；
6. 为每页选择最合适的布局、图表、图片或示意图；
7. 建立统一的视觉系统（色彩、字体、背景、图形、图片风格）；
8. 输出可直接交付给设计师 / PPT 生成模型 / 图像生成模型的页面方案；
9. 对整套方案做质量检查与自动修正。

## 工作流程

严格按顺序执行，**不允许从原始材料直接跳到页面排版**：

```mermaid
flowchart LR
    A[任务理解] --> B[内容审计]
    B --> C[观众分析]
    C --> D[沟通目标]
    D --> E[叙事结构]
    E --> F[页数与章节分配]
    F --> G[页面观点提炼]
    G --> H[页面视觉映射]
    H --> I[整体视觉系统]
    I --> J[单页布局设计]
    J --> K[过渡与节奏]
    K --> L[一致性检查]
    L --> M[输出最终方案]
```

## 七阶段方法论

### 1. 任务理解
先判断演示的本质任务：说服型 / 解释型 / 汇报型 / 教学型 / 发布型 / 证明型 / 品牌型 / 阅读型；并输出观众画像与「一句话目标」：

> 通过这份 PPT，让【目标观众】相信/理解【核心结论】，并愿意【采取行动】。

### 2. 内容审计
把材料分为核心结论、关键论据、数据证据、案例、背景、方法、结果、风险、路线图、可删除信息、待核验信息；按**必要性 / 可信度 / 差异性 / 可视化潜力 / 观众相关性**打分排序。事实遵循：已确认才使用、来源不明标「需核验」、冲突不擅自选择、预测必须标注。

### 3. 叙事结构
按场景选择结构而非套用模板，内置 6 套结构（见下节）。

### 4. 页数与节奏
结合时长、复杂度、页面密度定页数；参考节奏：路演 35–60 秒/页、学术 40–70 秒/页、发布 25–50 秒/页、教学 60–120 秒/页。章节比例参考：开场与问题 15–20%、主体方案 35–45%、证据与验证 20–30%、未来/团队/行动 15–20%。

### 5. 页面规划
每页只承担一个主要任务，标题写成**观点/结论**而不是栏目名（避免「项目背景」「市场分析」这类空泛标题），并逐页定义页面角色、核心信息、证据、视觉表达与过渡。

### 6. 整体视觉系统
先定全局再做单页：主题概念、3–5 个视觉关键词、配色（中性色 60–75% / 主色 15–25% / 强调色 5–10%）、字体（中文≤2 种、英文≤2 种）、网格与留白（20–35% 有效留白）、统一的图片/图表/图标/卡片风格。

### 7. 质量检查
从内容、结构、视觉、场景适配四个维度自检，按 100 分制打分，**低于 85 分自动修正后再输出**。

## 叙事结构模板

| 场景 | 主线 |
|---|---|
| 商业路演 | 问题 → 时机 → 痛点 → 洞察 → 方案 → 演示 → 技术壁垒 → 进展 → 市场 → 商业模式 → 优势 → 增长 → 团队 → 融资用途 → 愿景 |
| 学术答辩 | 背景 → 研究缺口 → 科学问题 → 目标 → 理论基础 → 方法与实验 → 关键结果 → 解释 → 对比验证 → 创新点 → 局限 → 结论 → 后续工作 |
| 工作汇报 | 目标 → 当前状态 → 关键成果 → 数据证明 → 主要问题 → 原因分析 → 解决方案 → 下阶段计划 → 资源需求 |
| 产品发布 | 真实场景 → 痛点 → 洞察 → 新品登场 → 核心体验 → 功能拆解 → 技术原理 → 效果证明 → 应用场景 → 获取方式 → 行动号召 |
| 教学课件 | 已有认知 → 现象/问题 → 概念引入 → 原理解释 → 模型 → 示例 → 常见误区 → 练习 → 迁移应用 → 总结 |
| 品牌/企业介绍 | 我们是谁 → 为何存在 → 服务谁 → 做什么 → 如何做 → 核心能力 → 代表成果 → 客户案例 → 未来方向 |

## 页面类型库

封面 · 问题 · 观点 · 并列 · 流程 · 对比 · 时间轴 · 数据 · 架构 · 实物/案例 · 团队 · 结束页，共 12 类，按内容关系选择，避免每页同构。结束页必须服务于最终行动，不能只写「谢谢观看」。

## 信息关系 → 视觉表达映射

| 内容关系 | 推荐表达 |
|---|---|
| 并列 | 卡片、分栏、矩阵 |
| 递进 | 阶梯、箭头、层级 |
| 流程 / 用户路径 | 流程图、路径图、输入—处理—输出 |
| 时间 | 时间轴、里程碑 |
| 对比 | 左右分屏、对比表 |
| 层级 / 构成 | 树状图、金字塔、分层拆解 |
| 趋势 / 数量 / 比例 / 相关 | 折线 / 柱状 / 环形 / 散点 |
| 因果 | 因果链、鱼骨图 |
| 空间结构 | 剖面图、示意图 |

> 禁止为了「好看」使用与逻辑不符的图形；无法增加理解时，宁可用干净文字。

## 标准输出格式

最终方案固定按 A–G 输出，达到可直接制作的详细程度：

- **A. 项目理解**：演示目标、观众、场景、时长、建议页数、一句话核心信息、期望行动、假设
- **B. 整体叙事结构**：章节划分与每章作用
- **C. 整体视觉风格**：主题、配色、字体、图片/图表/图标风格、网格、动效与禁忌
- **D. 每页详细规划**：页面角色、观点化标题、内容要点、证据、布局比例、阅读路径、素材、图表、来源、动效、上下页过渡、演讲焦点
- **E. 页面总览表**：页码 / 标题 / 角色 / 视觉形式 / 核心结论
- **F. 素材清单**：所需图片、图表、示意图、数据、Logo 与待核验项
- **G. 制作注意事项**：字体兼容、图片分辨率、数据来源、页面比例、演示设备、导出 PDF、备用版本、动效兼容、版权风险

## 质量评分机制

| 维度 | 分值 |
|---|---:|
| 沟通目标清晰度 | 10 |
| 内容筛选与观点提炼 | 20 |

## 安装与使用

### 方式一：作为 Skill 安装
将 `SKILL.md` 放入你的 Skill 目录（例如 `~/.agents/skills/ppt-architect-pro/SKILL.md`，或所用客户端对应的 skills 目录），重新加载后即可按名称调用。

### 方式二：直接作为系统提示词
把 `SKILL.md` 第 24 节「模型执行提示词」作为系统指令，再附上你的材料与需求即可。

### 调用模板

```text
请使用 PPT Architect Pro Skill，根据以下材料规划一套 PPT。

【演示场景】项目路演
【观众】早期投资人、产业专家
【演讲时长】8 分钟
【目标】让投资人理解产品价值、技术壁垒与商业化潜力，并愿意继续交流
【原始材料】粘贴材料或上传文件
【必须包含】项目初衷、产品功能、技术路径、当前进展、市场、商业模式、融资需求
【视觉偏好】克制、高级、科技感、真实，不要廉价炫光
【输出要求】逐页写清标题、内容、布局比例、图片、图表、配色、字体与页面过渡
```

## 高质量硬性规则

1. 一页一个主要结论；2. 标题优先写成观点；3. 内容服务演示目标；4. 不直接堆砌原材料；5. 内容关系决定视觉形式；6. 同级信息同级表达；7. 重要信息形成视觉对比；8. 视觉系统全局统一；9. 图片真实清晰相关；10. 图表必须有结论；11. 数据标注来源；12. 不用无关装饰；13. 不为「高级感」牺牲可读性；14. 不让每页像独立海报；15. 结束页形成行动或记忆点。

## 常见失败模式与修正

| 失败模式 | 表现 | 修正 |
|---|---|---|
| 材料搬运 | 大段复制原文、页面像 Word | 提炼结论 → 删噪音 → 分层级 → 图形化 |
| 平均用力 | 文字一样大、无焦点 | 突出一个核心，用字号/字重/颜色/留白制造层级 |
| 风格混乱 | 图片配色不统一 | 回到视觉系统，统一组件，删除无法统一的装饰 |
| 伪可视化 | 用图形装饰文字、与逻辑无关 | 先判信息关系再选图表，否则用干净文字 |
| 过度设计 | 炫光渐变过多、信息被淹没 | 删非必要元素、增加留白、强化主次 |
